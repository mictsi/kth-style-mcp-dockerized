Design tokens for coding agents

Your agent should not guess KTH blue.

It should read the exact value out of the installed @kth/style package — and say which file and line it came from.

kth-style-mcp indexes the KTH Style package and serves it over MCP, so the agent writing your components asks for tokens, imports, class names and theme contexts instead of approximating them.

What it reads

Everything is parsed out of the package on disk. Nothing is hand-copied into this server, so it does not drift when KTH Style ships a release.

Run it

One container. It serves MCP over Streamable HTTP and needs nothing from your project.

01 / START

Bring the container up

Builds the image and starts it on loopback. run.sh also does stop, logs, status and clean.

# from the repo root
./run.sh run --build
02 / CONNECT

Point your agent at it

Any MCP client that speaks Streamable HTTP. Set BASE_PATH when you publish it behind a reverse proxy.

{
  "mcpServers": {
    "kth-style": {
      "type": "http",
      "url": "http://127.0.0.1:8888/mcp"
    }
  }
}
03 / CHECK

Confirm it answers

The health route reports the resolved paths, so you can see exactly what your client should call.

curl 127.0.0.1:8888/healthz

{"status":"ok",
 "mcpPath":"/mcp"}

tools called by the agent, not by you

Where it fits in the loop

You keep writing prompts in your own words. The server changes what the agent does next: instead of recalling a hex value or inventing a class name, it looks them up and cites them.

Starting a new page

Ask for the shell and the agent pulls the scaffold, the header wiring and the entrypoints for the variant you named.

  • suggest_theme_structure — which entrypoints and scripts a public, intranet, student-web or external app needs
  • get_page_scaffold — the section order for that variant
  • get_header_recipe — dialog hooks, data-id pairing and the variant classes the header expects

Building a component

Ask for a table, an alert, a mobile menu. The agent gets the import path, the real class names and the tokens that component consumes.

  • get_component_guidance — any of the 23 components, plus the navigation and modal aliases
  • kth_style_get_token — one exact value, per theme context
  • get_icon — SVG content, the data-URI variable and the SCSS mixin name

unresolved values return diagnostics — never an approximation

The tools

The kth_style_* tools are the authoritative ones: their responses carry the package version and a source field recording how the package was found.

kth_style_get_theme

A whole context: reference tokens, semantic tokens, assets and the SCSS to import.

kth_style_get_token

One exact token, optionally resolved for a named theme context.

kth_style_list_tokens

Reference and semantic families listed separately, with file and line.

kth_style_list_components

Component import paths exactly as the installed package publishes them.

kth_style_get_package_info

Version, package path, asset root and how the package was discovered.

get_component_guidance

Per component: classes, tokens, mixins, icons and the theme variants it declares.

get_header_recipe

Header and navigation wiring, including the legacy local-navigation IDs.

get_page_scaffold

A deterministic page shell for each theme variant.

suggest_theme_structure

Entrypoints, tokens, scripts and components for an app shape.

search_tokens

Substring search across primitive tokens and parsed theme variables.

search_mixins

Typography, theme and icon helper mixins with their signatures.

search_icons

Icons and logotypes by name, mixin or path.

get_icon

SVG content, data-URI variable and SCSS mixin for one icon.

search_styles

Line-based search across the authored SCSS and TypeScript.

get_entrypoints

The SCSS, CSS and JS entrypoints to reach for first.

refresh_catalog

Rebuild the index after the package changes underneath you.

Where the values come from

The server reports its own provenance so you can tell an authoritative answer from a fallback. If it cannot find the package, tools return a structured diagnostic rather than a plausible guess.

DEFAULT

installed

The node_modules/@kth/style found by walking up from the server. This is what the container runs.

OVERRIDE

source-dir

Set KTH_STYLE_SOURCE_DIR to a monorepo checkout when you are developing KTH Style itself.

FLAGGED

monorepo-default

A legacy ../style fallback. It still answers, but every response carries a warning that it is not package-backed.
